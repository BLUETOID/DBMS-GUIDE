2.1 Relational Data Model Concepts

Introduced by Dr. E.F. Codd (1970) at IBM, the Relational Data Model represents data as a collection of two-dimensional mathematical tables termed relations.

Formal Mathematical Definitions

  • Domain (D): A set of atomic, indivisible values of identical data type (e.g., Domain(Salary) = Real numbers > 0).
  • Attribute (Ai): The named column of a relation representing the role of a domain in a relation schema.
  • Tuple (t): An ordered list of values t = ⟨v1, v2, ..., vn⟩ representing a row where vi ∈ Domain(Ai).
  • Relation Schema (R): Denoted by R(A1, A2, ..., An), defining the table name and attribute domains.
  • Relation Instance (r(R)): A mathematical relation over domains, defined as a subset of the Cartesian product:
    r(R) ⊆ D1 × D2 × ... × Dn
  • Degree (Arity): The total number of attributes (columns) in a relation schema.
  • Cardinality: The total number of tuples (rows) currently in a relation instance.
  • NULL: A special marker indicating missing, unknown, or inapplicable attribute values.

2.2 Relational Integrity Constraints

Integrity constraints are declarative assertions that every legal database state must satisfy. The database engine rejects any DML operation that violates these rules.

Constraint Mathematical Invariant Enforcement & Cascading Rules
Domain Constraint For each attribute A, t[A] ∈ Domain(A) ∪ {NULL}. Data types, range limits (CHECK (Salary > 0)), regex format checks.
Key Constraint No two distinct tuples can have identical candidate key values:
∀ t1, t2 ∈ r, t1[K] = t2[K] ⇒ t1 = t2.		 PRIMARY KEY and UNIQUE constraints enforced using B+ Tree indexes.
Entity Integrity No primary key attribute value can be NULL:
∀ t ∈ r(R), t[PK] ≠ NULL.		 Guarantees that every individual tuple in the relation is distinctly identifiable.
Referential Integrity Foreign key FK in child relation R1 must match a valid primary key in parent relation R2 (or be NULL). ON DELETE CASCADE (deletes child), ON DELETE SET NULL, ON DELETE RESTRICT (aborts parent delete).

2.3 Relational Algebra Operators

Relational Algebra is a theoretical procedural query language that accepts relations as input and yields a new relation as output.

Operator Mathematical Notation Formal Semantics & Example
Selection σp(r) Filters tuples satisfying predicate p:
σDept = 'CSE' ∧ Salary > 60000(INSTRUCTOR)
Projection πL(r) Extracts specified attributes L and eliminates duplicates:
πName, Salary(INSTRUCTOR)
Cartesian Product r × s Combines every tuple of r with every tuple of s. Cardinality = |r| × |s|; Degree = Deg(r) + Deg(s).
Union r ∪ s Combines tuples from both relations. Requires Union Compatibility (same degree and domain types).
Set Difference r − s Returns tuples present in r but absent in s (requires Union Compatibility).
Natural Join r ⨝ s Equijoin over identically named common attributes, eliminating duplicate join columns.
Division Operator r ÷ s Formulates universal "for all" queries: tuples in r[R − S] associated with every tuple in s.

Worked Example 2.1: Cartesian Product vs Natural Join vs Outer Join Trace

Consider the following two university relations with active instances:

Step-by-Step Operator Comparison:
  1. Cartesian Product ($STUDENT \times ENROLL$): Combines all 3 rows of STUDENT with all 4 rows of ENROLL → exactly $3 \times 4 = 12$ tuples, degree = $3 + 3 = 6$.
  2. Natural Join ($STUDENT \bowtie ENROLL$): Equates shared attribute RollNo and projects union of columns without duplication:
    RollNoSNameMajorCourseIDSem
    1AliceCSECS1013
    1AliceCSECS1023
    2BobECEEC2013
    Result: 3 tuples. Charlie (RollNo 3) and Student 4 are omitted because no match exists.
  3. Left Outer Join ($STUDENT \leftouterjoin ENROLL$): Retains Charlie (RollNo 3) and pads unmatched ENROLL columns with NULL: (3, 'Charlie', 'ME', NULL, NULL).

Worked Example 2.2: Relational Division (R ÷ S) Evaluation Protocol

Relation R (Student_Course): Enrolled pairs (Roll_No, Course_ID)

Relation S (Mandatory_Courses): Required set Course_ID ∈ {CS101, CS102}

  1. All students: πRoll_No(R) = {101, 102, 103}
  2. All required course combinations: πRoll_No(R) × S = {(101, CS101), (101, CS102), (102, CS101), (102, CS102), (103, CS101), (103, CS102)}
  3. Missing enrollments: (πRoll_No(R) × S) − R = {(103, CS102)}
  4. Students with missing requirements: πRoll_No(Missing) = {103}
  5. Final Qualified Students: {101, 102, 103} − {103} = {101, 102}

2.5 Relational Calculus (TRC & DRC)

Unlike procedural Relational Algebra, Relational Calculus is a non-procedural, declarative formal logic language.

1. Tuple Relational Calculus (TRC)

Variables represent complete rows (tuples): { t | P(t) }

Example: Find instructors in 'CSE' earning > 80,000:

{ t | ∃ i ∈ INSTRUCTOR ( i[Dept] = 'CSE' ∧ i[Salary] > 80000 ∧ t[Name] = i[Name] ) }

2. Domain Relational Calculus (DRC)

Variables represent individual attribute values: { ⟨x1, x2, ... xn⟩ | P(x1, x2, ... xn) }

Safety of Calculus Expressions

An expression like { t | ¬(t ∈ r) } is unsafe because it evaluates to an infinite set of tuples outside the database. An expression is safe if all output values originate from the finite active domain of the database.

2.6 SQL Query Optimization Pipeline

The RDBMS engine parses, validates, and transforms declarative SQL queries into algebraic expression trees, optimizing them before execution.

2.7 SQL Foundations & Data Types

Data Type Storage Characteristic Usage Best Practice
CHAR(n) Fixed-length character string, blank-padded. State codes ('NY'), country codes ('IND').
VARCHAR2(n) Variable-length character string up to n bytes. Names, addresses, emails, dynamic texts.
NUMBER(p, s) Precision p, scale s exact decimal. Currency, banking balances, GPA (NUMBER(3, 2)).
INT / BIGINT 4-byte / 8-byte signed binary integer. Surrogate keys, auto-increment identifiers.
DATE / TIMESTAMP Calendar date with fractional seconds and timezone. Transaction logs, audit trails, event timestamps.

2.8 The 5 SQL Command Families

sql_families.sql 
-- 1. DDL: Schema Creation
CREATE TABLE Student (
    Roll_No INT PRIMARY KEY,
    Name VARCHAR(50) NOT NULL,
    GPA NUMERIC(3, 2) CHECK (GPA BETWEEN 0.0 AND 10.0)
);

-- 2. DML: Data Modification
INSERT INTO Student VALUES (101, 'Alice Johnson', 9.45);
UPDATE Student SET GPA = 9.60 WHERE Roll_No = 101;

-- 3. DQL: Data Querying
SELECT Roll_No, Name FROM Student WHERE GPA >= 9.0;

-- 4. DCL: Permission Grants
GRANT SELECT ON Student TO faculty_role;

-- 5. TCL: Transaction Boundaries
SAVEPOINT before_update;
UPDATE Student SET GPA = 9.70 WHERE Roll_No = 101;
COMMIT; -- Permanently stores state updates

2.9 Views, Indexes & B+ Trees

A View is a virtual table defined by an underlying stored SQL query. It does not duplicate physical data on disk.

views_and_indexes.sql 
-- Create View with Security Constraint
CREATE VIEW HonorRollStudents AS
SELECT Roll_No, Name, GPA
FROM Student
WHERE GPA >= 9.0
WITH CHECK OPTION;

-- Clustered vs Secondary B+ Tree Index
CREATE INDEX idx_student_gpa ON Student(GPA);

2.10 Subqueries & Correlated Logic

Correlated subqueries reference columns from the outer query, executing once per candidate outer row.

correlated_subquery.sql 
-- Employees earning above their department's average salary
SELECT E.Emp_ID, E.Name, E.Salary, E.Dept_ID
FROM Employee E
WHERE E.Salary > (
    SELECT AVG(D.Salary)
    FROM Employee D
    WHERE D.Dept_ID = E.Dept_ID
);

2.11 Aggregations & Window Functions

Logical SQL Execution Order

FROM → WHERE → GROUP BY → HAVING → SELECT → WINDOW → DISTINCT → ORDER BY → LIMIT

window_functions.sql 
-- RANK() vs DENSE_RANK() Over Department Partitions
SELECT 
    Emp_ID, Name, Dept_ID, Salary,
    RANK() OVER (PARTITION BY Dept_ID ORDER BY Salary DESC) AS rnk,
    DENSE_RANK() OVER (PARTITION BY Dept_ID ORDER BY Salary DESC) AS dense_rnk
FROM Employee;

2.14 PL/SQL: Blocks, Cursors & Triggers

salary_audit_trigger.sql 
-- Row-Level Audit Trigger with :OLD and :NEW Pseudorecords
CREATE OR REPLACE TRIGGER trg_audit_salary
AFTER UPDATE OF Salary ON Employee
FOR EACH ROW
BEGIN
    INSERT INTO Salary_Audit (
        Emp_ID, Old_Salary, New_Salary, Changed_By, Change_Date
    ) VALUES (
        :OLD.Emp_ID, :OLD.Salary, :NEW.Salary, USER, SYSDATE
    );
END;

2.15 PL/SQL Stored Procedures & Transactions

transfer_funds.sql 
-- Atomic Bank Fund Transfer Stored Procedure
CREATE OR REPLACE PROCEDURE TransferFunds (
    p_src_acc IN INT,
    p_dest_acc IN INT,
    p_amount IN NUMERIC,
    p_status OUT VARCHAR2
) AS
    v_balance NUMERIC;
BEGIN
    SELECT Balance INTO v_balance FROM Account WHERE AccNo = p_src_acc FOR UPDATE;
    IF v_balance < p_amount THEN
        p_status := 'INSUFFICIENT_FUNDS';
        ROLLBACK;
        RETURN;
    END IF;

    UPDATE Account SET Balance = Balance - p_amount WHERE AccNo = p_src_acc;
    UPDATE Account SET Balance = Balance + p_amount WHERE AccNo = p_dest_acc;
    COMMIT;
    p_status := 'SUCCESS';
EXCEPTION
    WHEN OTHERS THEN
        ROLLBACK;
        p_status := 'ERROR';
END;
/

2.16 Solved Exam Query Formulations

University Sailor-Boat Schema:

  • SAILOR(Sid, Sname, Rating, Age)
  • BOAT(Bid, Bname, Color)
  • RESERVES(Sid, Bid, Day)
query1_universal_division.sql 
-- Query 1: Find sailors who have reserved ALL red boats (Universal Division in SQL)
SELECT S.Sid, S.Sname
FROM SAILOR S
WHERE NOT EXISTS (
    SELECT B.Bid FROM BOAT B WHERE B.Color = 'Red'
    EXCEPT
    SELECT R.Bid FROM RESERVES R WHERE R.Sid = S.Sid
);
query2_multiple_reservations.sql 
-- Query 2: Find sailors who have reserved at least two distinct boats (Correlated / Self-Join)
SELECT DISTINCT S.Sid, S.Sname
FROM SAILOR S
JOIN RESERVES R1 ON S.Sid = R1.Sid
JOIN RESERVES R2 ON S.Sid = R2.Sid
WHERE R1.Bid <> R2.Bid;
query3_group_having.sql 
-- Query 3: Find average age of sailors for each rating level having at least 2 sailors
SELECT Rating, AVG(Age) AS Avg_Age, COUNT(*) AS Sailor_Count
FROM SAILOR
GROUP BY Rating
HAVING COUNT(*) >= 2
ORDER BY Rating ASC;
query4_second_highest_rating.sql 
-- Query 4: Find sailors with the second highest rating without using LIMIT
SELECT *
FROM SAILOR
WHERE Rating = (
    SELECT MAX(Rating)
    FROM SAILOR
    WHERE Rating < (SELECT MAX(Rating) FROM SAILOR)
);
