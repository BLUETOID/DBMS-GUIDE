3.1 Functional Dependencies (FD)

Normalization is the formal mathematical process of evaluating relational schemas to eliminate insertion, deletion, and update anomalies while minimizing data redundancy.

Formal Definition of Functional Dependency

Let R be a relation schema and X, Y ⊆ R be attribute subsets. A Functional Dependency denoted by X → Y specifies that whenever two tuples agree on attribute set X, they must agree on attribute set Y:

∀ t1, t2 ∈ r(R),   if t1[X] = t2[X] ⇒ t1[Y] = t2[Y]

We state that "X functionally determines Y". X is the determinant, and Y is the dependent.

Classification of Dependencies:

  • Trivial FD: An FD X → Y is trivial if Y ⊆ X (e.g., {Roll_No, Name} → Roll_No). Always satisfied.
  • Non-Trivial FD: An FD X → Y is non-trivial if Y is not a subset of X. It is completely non-trivial if X ∩ Y = ∅.
  • Full Functional Dependency: X → Y is full if removing any attribute A from X destroys the dependency (irreducible determinant).
  • Partial Dependency: X → Y is partial if Y depends on a proper subset of candidate key X.
  • Transitive Dependency: If X → Y and Y → Z hold where Y ↛ X and Z ⊄ Y, then X → Z is a transitive dependency.

3.2 Armstrong's Axioms and Formal Proofs

Armstrong's Axioms (1974) form a sound and complete inference system for computing the complete closure of functional dependencies (F+).

Rule Name Formal Mathematical Notation Axiom Classification
Reflexivity If Y ⊆ X, then X → Y Primary Axiom
Augmentation If X → Y, then XZ → YZ for any attribute set Z Primary Axiom
Transitivity If X → Y and Y → Z, then X → Z Primary Axiom
Union If X → Y and X → Z, then X → YZ Derived Secondary Rule
Decomposition If X → YZ, then X → Y and X → Z Derived Secondary Rule
Pseudo-transitivity If X → Y and WY → Z, then WX → Z Derived Secondary Rule

3.3 Attribute Closure Algorithm (X+)

The Attribute Closure X+ is the set of all attributes that are functionally determined by X under dependency set F.

Attribute Closure Algorithm

  1. Initialize X+ = X.
  2. Repeat until no new attributes can be added:
    For each FD Y → Z ∈ F:
    If Y ⊆ X+, then X+ = X+ ∪ Z.
  3. Output X+.

Candidate Key Test: If X+ equals all attributes of relation R and no proper subset of X determines R, then X is a Candidate Key.

3.4 Canonical / Minimal Cover (Fc)

A Minimal Cover Fc is an equivalent, non-redundant canonical representation of FD set F:

  1. Standard Form: Decompose all RHS attributes into singletons (e.g., A → BC becomes A → B and A → C).
  2. Extraneous Attribute Elimination: For each FD X → A, remove extraneous attributes B from LHS determinant if (X - {B})+ contains A.
  3. Redundant FD Elimination: For each remaining FD f ∈ F, if f can be inferred from F - {f}, delete f.

3.6 1NF, 2NF & Prime Attributes

  • First Normal Form (1NF): All attribute domains contain only atomic, indivisible scalar values. No repeating groups, arrays, multi-valued attributes, or nested relations.
  • Prime Attribute: An attribute that is a member of at least one Candidate Key. All other attributes are non-prime.
  • Second Normal Form (2NF): Must be in 1NF and have NO Partial Dependencies. Every non-prime attribute must depend on the whole candidate key, not a proper subset of it.

Unnormalized Table (Violates 1NF): Column Enrolled_Courses contains non-atomic, multi-valued comma-separated arrays:

3.7 Third Normal Form (3NF)

3NF Formal Condition

A relation schema R is in 3NF if it is in 2NF and, for every non-trivial FD X → Y, at least ONE of the following holds:

  • 1. X is a Superkey of relation R, OR
  • 2. Y is a Prime Attribute (each attribute in Y is a member of at least one candidate key).

Core Rule: 3NF eliminates all Transitive Dependencies: non-prime attributes must not depend on other non-prime attributes.

3NF Concrete Example: Transitive Dependency Elimination

Relation with Transitive Dependency (Violates 3NF): Primary Key is Emp_ID.

Emp_ID → Dept_ID and Dept_ID → Dept_Name ⇒ Therefore, Emp_ID → Dept_Name is a Transitive Dependency through non-prime determinant Dept_ID.

3.8 Boyce-Codd Normal Form (BCNF)

BCNF Strict Rule

A relation schema R is in BCNF if, for every non-trivial functional dependency X → Y holding in R:

X must be a SUPERKEY of R

Key Difference: BCNF strictly disallows the "Y is a prime attribute" exception. Every determinant attribute set must independently identify tuples.

BCNF Concrete Example: Relation in 3NF but Violating BCNF

Consider STUDENT_ADVISOR(Student_ID, Subject, Advisor) with constraints:

  • A student can take multiple subjects.
  • For each subject, a student is assigned one advisor: {Student_ID, Subject} → Advisor.
  • Each advisor teaches only one subject: Advisor → Subject.

3.9 Inclusion Dependencies

An Inclusion Dependency R1.X ⊆ R2.Y specifies that the values appearing in columns X of table R1 must also appear in columns Y of table R2. This is the mathematical formalization of foreign key referential integrity constraints.

3.10 Lossless Join & Matrix Chase Test

A decomposition D = {R1, R2} of R is lossless if natural join reconstructs the exact original relation without spurious tuples:

R1 ⨝ R2 = R  ⇔  (R1 ∩ R2) → (R1 - R2)  ∨  (R1 ∩ R2) → (R2 - R1)

The common attribute set must be a superkey of at least one of the decomposed tables.

3.11 Dependency Preservation

A decomposition is dependency preserving if enforcing projected FDs locally on each decomposed table is sufficient to enforce all original functional dependencies:

(F1 ∪ F2 ∪ ... ∪ Fk)+ = F+

While 3NF guarantees both lossless join and dependency preservation, BCNF can sometimes lose dependencies that span multiple tables.

3.12 Multi-Valued Dependencies (MVD) & Fourth Normal Form (4NF)

A Multi-Valued Dependency (MVD) X ↠ Y specifies that the presence of certain tuples in relation R implies the presence of other tuples. In essence, attribute set Y is independent of the remaining attributes in relation R given attribute set X.

4NF Condition

A relation schema R is in 4NF if it is in BCNF and, for every non-trivial MVD X ↠ Y holding in R, X is a Superkey of R.

4NF Concrete Example: Cartesian Product Anomaly

Consider INSTRUCTOR_INFO(Instructor, Course, Hobby) where an instructor teaches multiple courses and pursues multiple independent hobbies:

InstructorCourseHobby

Dr. RajeshAlgorithmsCricket

The Anomaly: Because Course and Hobby are mutually independent, adding a 3rd hobby requires inserting 2 additional tuples (one for each course). This Cartesian explosion is resolved by 4NF decomposition:

3.13 Join Dependencies & Fifth Normal Form (5NF)

A relation schema is in 5NF (Project-Join Normal Form / PJNF) if every non-trivial Join Dependency ⨝[R1, R2, ... Rn] is implied by the candidate keys of R. 5NF eliminates cyclic join redundancy.

3.14 3NF Synthesis Algorithm (Bernstein's Algorithm)

3NF Synthesis Steps (Guarantees Lossless + Dependency Preservation)

  1. Find a Minimal Cover Fc of F.
  2. For each FD X → Y ∈ Fc, create relation schema Ri = X ∪ Y.
  3. If none of the schemas contains a candidate key of R, add schema Rk = K where K is any candidate key.
  4. Eliminate redundant sub-schemas (if Rj ⊆ Ri, drop Rj).

3.15 Lossless BCNF Decomposition Algorithm

Recursive BCNF Decomposition

  1. Initialize D = {R}.
  2. While there exists a relation Ri ∈ D not in BCNF:
    • Find non-trivial FD X → Y on Ri violating BCNF (X is not superkey).
    • Decompose Ri into R1 = X ∪ Y and R2 = Ri - (Y - X).
    • Replace Ri with R1 and R2 in D.

3.16 Solved Exam Numerical Problems

Problem 1: Minimal Cover Computation

Given FD Set: F = { A → BC, B → C, A → B, AB → C }

  1. RHS Decomposition: F1 = { A → B, A → C, B → C, AB → C }
  2. Extraneous Attribute: In AB → C, test B: A+ = {A, B, C} under F1. Since C ∈ A+, B is extraneous → becomes A → C.
  3. Redundant FD: In { A → B, A → C, B → C }, test A → C: without it, A+ = {A, B, C} via Transitivity. Thus A → C is redundant.
  4. Final Minimal Cover: Fc = { A → B, B → C }

Problem 2: Complete Multi-Candidate Key Determination

Systematic Candidate Key Algorithm

Relation Schema: $R(A, B, C, D, E)$ with functional dependencies: $$F = \{ AB \to C, \; C \to D, \; D \to E, \; E \to A \}$$

  1. Essential Attribute Identification: Inspect the right-hand side of all FDs: $\{C, D, E, A\}$. Attribute $B$ never appears on any RHS. Therefore, $B$ must belong to every candidate key.
  2. Closure of $AB$: $$(AB)^+ = \{A, B\} \xrightarrow{AB \to C} \{A, B, C\} \xrightarrow{C \to D} \{A, B, C, D\} \xrightarrow{D \to E} \{A, B, C, D, E\} = R$$ Since no proper subset of $\{AB\}$ determines all attributes, $K_1 = \{A, B\}$ is a Candidate Key.
  3. Substitution via Dependencies:
    • Since $E \to A$, replace $A$ with $E$: $$(EB)^+ = \{A, B, C, D, E\} \implies \mathbf{K_2 = \{E, B\}}$$
    • Since $D \to E$, replace $E$ with $D$: $$(DB)^+ = \{A, B, C, D, E\} \implies \mathbf{K_3 = \{D, B\}}$$
    • Since $C \to D$, replace $D$ with $C$: $$(CB)^+ = \{A, B, C, D, E\} \implies \mathbf{K_4 = \{C, B\}}$$
  4. Candidate Keys of R: $\{AB\}, \{EB\}, \{DB\}, \{CB\}$.
  5. Prime Attributes: $\{A, B, C, D, E\}$ (All attributes are prime!).
  6. Normal Form Determination: Since every attribute in $R$ is prime, condition (ii) of 3NF ($A$ is a prime attribute) holds for all FDs. Therefore, $R$ is guaranteed to be in 3NF.

Problem 3: Lossless Join & Dependency Preservation Test

Complete Decomposition Verification

Relation: $R(A, B, C, D)$ with $F = \{ A \to B, \; B \to C, \; C \to D, \; D \to A \}$. Decomposed into $R_1(A, B, C)$ and $R_2(C, D)$.

  1. Lossless Join Verification: $$R_1 \cap R_2 = \{C\}$$ Compute closure of the common attribute set under $F$: $$C^+ = \{C\} \xrightarrow{C \to D} \{C, D\} \xrightarrow{D \to A} \{C, D, A\} \xrightarrow{A \to B} \{A, B, C, D\} = R$$ Since $(R_1 \cap R_2)^+ \supseteq R_2$, the common attribute set is a Superkey of $R_2$. Therefore, the decomposition is strictly Lossless Join.
  2. Dependency Preservation Verification:
    • $A \to B$ and $B \to C$ only contain attributes in $R_1$, so they are preserved in $F_1$.
    • $C \to D$ only contains attributes in $R_2$, so it is preserved in $F_2$.
    • To check $D \to A$: $(D)^+$ under $F_1 \cup F_2$: $D$ in $R_2$ doesn't produce $A$ directly, but since $D \to A$ is logically implied via $D \to A$ if joined, let's verify if $(F_1 \cup F_2)^+ = F^+$. Here $F_1 = \{A \to B, B \to C, A \to C\}$, $F_2 = \{C \to D\}$. Without $D \to A$, closure of $D$ under $F_1 \cup F_2$ is only $\{D\}$. Thus $D \to A$ is NOT preserved.
